## Not yet complete — do not treat this build as production-ready

- Purchasing gaps: supplier invoice reconciliation now records the declared invoice total, compares it with cumulative received goods value, requires an explanation for any variance, and exposes matched/variance-explained status. Supplier tax/charges allocation and credit-note reconciliation remain accountant-policy dependent. Multi-batch partial receiving, short-delivery discrepancy capture, actual received-value accounting and supplier balances are implemented with service tests; packaged E2E covers multi-batch receiving. Supplier returns, invoice-level partial/full payments, age buckets, overpayment blocking, AP/inventory and AP/cash journals, and audit/outbox records are service-tested.
- Accounting gaps: inventory valuation ledger, account-specific payment clearing, full indirect-method cash-flow statement and accountant-approved tax/reporting policy. Supplier settlement/aging, manual journals/reversals, trial balance, income statement, balance sheet and cash/clearing movement statement are implemented and covered by service tests. The cash movement statement is a ledger movement summary, not a full indirect-method cash-flow statement. Default posting matrix remains provisional until signed off.
- Central sync baseline now exists in `sync-server/`: PostgreSQL event ingestion, authenticated counter provisioning, product/stock/sale/customer-return/supplier-return processing, counter stock allocations, snapshot pull, local allocation enforcement and conflict list/resolution API. Local PostgreSQL integration checks pass, including supplier returns reducing the originating counter's allocation. Still open: comprehensive business-event coverage, multi-counter concurrency/restore acceptance tests, provisioning/recovery UX and production TLS deployment. A basic central operations UI is available at `/admin` for stock adjustment, counter allocation and conflict review/resolution. Secure in-app endpoint/token configuration is implemented with OS secure storage; store settings snapshots are included in the central API.
- Full branding acceptance: logo asset management, historical receipt branding verification and direct thermal-printer hardware testing.
- Report gaps: category sales and gross-margin reporting are now available using checkout-time cost snapshots; historical rows without snapshots are explicitly marked as incomplete cost coverage; stock value is an estimate using current purchase cost, not a posted perpetual accounting valuation. The cash movement statement summarizes cash/clearing ledger entries and is not a full indirect-method cash-flow statement. Purchases are not fully integrated into all financial statements.
- End-to-end acceptance on real store data, actual Windows installer/upgrade tests, Linux install/uninstall/data-preservation tests and physical peripheral/hardware testing.
- Performance/accessibility acceptance against SRS target hardware and datasets.

## Release rule

Do not claim full SRS completion until each acceptance test in `docs/SRS_v1.1.md`, `docs/BRANDING_REQUIREMENTS.md`, and `docs/DESIGN_AND_INVENTORY_REQUIREMENTS.md` has implementation evidence and has passed. Do not use this current development build for real financial operations until the remaining workflows, accounting policy, backups, printer, packaged delivery and business acceptance are verified.

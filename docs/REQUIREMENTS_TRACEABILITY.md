**Baseline:** `docs/SRS_v1.1.md`, `docs/BRANDING_REQUIREMENTS.md`, and `docs/DESIGN_AND_INVENTORY_REQUIREMENTS.md`.

This document separates implemented code from acceptance-tested behavior. A database table or a route alone does not count as a finished business workflow.

## Not yet complete — do not treat this build as production-ready

- Purchasing gaps: supplier balance tracking, supplier invoice reconciliation, supplier payment settlement, partial goods receiving and discrepancy handling. Supplier returns now have a dedicated modal, stock-availability/received-quantity enforcement, audit/outbox and balanced AP/inventory posting; service tests pass. Purchasing/return UI still needs packaged interaction coverage.
- Accounting gaps: supplier settlement/aging, inventory valuation ledger, account-specific payment clearing, balance sheet/cash-flow statements and accountant-approved tax/reporting policy. Manual journals/reversals, trial balance and income statement are implemented and covered by service/UI smoke tests. Default posting matrix remains provisional until signed off.
- Central sync baseline now exists in `sync-server/`: PostgreSQL event ingestion, authenticated counter provisioning, product/stock/sale/return processing, counter stock allocations, snapshot pull, local allocation enforcement and conflict list/resolution API. Local PostgreSQL integration smoke checks pass. Still open: comprehensive business-event coverage, multi-counter concurrency/restore acceptance tests, provisioning/recovery UX and production TLS deployment. A basic central operations UI is available at `/admin` for stock adjustment, counter allocation and conflict review/resolution. Secure in-app endpoint/token configuration is implemented with OS secure storage; store settings snapshots are included in the central API.
- Full branding acceptance: logo asset management, historical receipt branding verification and direct thermal-printer hardware testing.
- Report gaps: no cashier/category/gross-margin, balance-sheet or cash-flow reports yet; stock value is an estimate using current purchase cost, not a posted accounting valuation. Purchases are not fully integrated into financial statements.
- End-to-end acceptance on real store data, actual Windows installer/upgrade tests, Linux install/uninstall/data-preservation tests and physical peripheral/hardware testing.
- Performance/accessibility acceptance against SRS target hardware and datasets.

## Release rule

Do not claim full SRS completion until each acceptance test in `docs/SRS_v1.1.md`, `docs/BRANDING_REQUIREMENTS.md`, and `docs/DESIGN_AND_INVENTORY_REQUIREMENTS.md` has implementation evidence and has passed. Do not use this current development build for real financial operations until the remaining workflows, accounting policy, backups, printer, packaged delivery and business acceptance are verified.
